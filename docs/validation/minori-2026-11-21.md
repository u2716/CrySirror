Each invocation used the following command with its own temporary data directory. The desktop host opened the original files in place.

```sh
./target/release/crysirror play "$HOME/Downloads/$installation" \
    --headless --no-audio --frames 600 --data-dir "$temporary_root/$installation"
```

A separate read-only diagnostic independently decoded the eden* script-bank index and checked all 25 member extents. It contains a 22-byte `test.sc` entry with storage method 0. The installed executable matches both known script-bank Blowfish key fingerprints. The reader expects the member password to occur as a contiguous eight-byte sequence; that fingerprint did not match the executable. This locates the failure before member decode and script dispatch. The other two samples failed at index-parameter selection. These results give no evidence for changing opcode dispatch or selecting a VM by title.

The current workspace passed `cargo test --release -p crysirror-minori`: 43 unit tests and one authored scenario integration test. That scenario reached the VM through CrySirror and exercised include, global state, chain-to-label and input. It uses loose authored scripts, so it does not exercise retail PAZ decoding.
