# CVNS Windows i386 profile from 2004-05-15

2026-11-19. IDA verified the PSS0 loader, CPZ1 table, 544-entry syscall jump
table, the 229 cases sharing the original no-effect handler and the native
frame-period set and query. The selector uses the PE machine and timestamp,
CVNS configuration and PSS0 startup signature. The game supplied these
resources through scoped read-only access.

The Release CMVS test run passed 39 library tests, one synthetic CVNS test
and 16 script tests. A separate run enabled the CVNS corpus test. It opened
all 89 members of the original `script.cpz` through the shared registry and
parsed their PSS0 containers. The decoder accepted all 270 instructions in
`start.pss` and all 72,315 instructions in `main.pss`.
A broader linear instruction sweep encountered an unsupported `0xfffc`
word in another member, so the corpus check covers complete container reads
and instruction decoding of the two named scripts.

The rebuilt Release desktop player selected CVNS and executed the original
`start.pss` through its frame-period setter with `play --headless --no-audio`.
It reported the first unreviewed syscall at `start.pss+0x1e`, selector
`0x210e`, and exited 1. The run created no window and emitted no audio.
The same build ran 240 headless muted frames of AMATSUTSUMI and KUNADO from
isolated state directories. Both exited zero in `logo.ps3`. These are
startup regressions. Menu and story acceptance remain open.

2026-11-19. After the CMVS fixed-scene changes, the Release desktop player
again selected the CVNS sample `MJGAMEDISC` and stopped on the same
audit-enable call at `start.pss+0x1e` with no window or audio output.
The standalone Release corpus check again opened all 89 script members.
The next implementation starts at the native bank audit `0x210e`, its
bit-bank operations `0x2108`–`0x210a`, and the numbered resource source
registration `0x2023`. The startup PCs are in the adapter's
[native ABI record](../../crates/crysirror-cmvs/NATIVE_ABI.md).
