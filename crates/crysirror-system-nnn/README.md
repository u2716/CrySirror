# System-NNN native adapter

This first-class crate implements the original word-addressed SPT VM and thin
native policies. Expressions, variables, structured control and script transfers
run on cancellation-aware workers. Only the owner commits client-scoped engine
calls and acknowledges the exact pending native receipt. Unknown operations keep
their original PC and fail explicitly.

`installed` (feature `runtime`) supplies a dormant factory. First step admits
capability-based bootstrap work; it reads original MSI/configuration/script data,
verifies the reviewed callback module SHA and prepares engine-owned resources.
No original executable or embedded engine core runs. The desktop detects the
reviewed installed/media profile; registration does not establish playable-game
completion.

Reusable implementation belongs to CrySirror:

- Black Cyc archives, DWQ images and VAW wrappers use the shared resource/image
  registries. Native filename, pack precedence, alpha-mask identity and
  load/preload assignment rules remain here.
- Retained Layers and frozen Canvases own composition. Immutable ImageResources,
  asynchronous canvas capture and image jobs own raster work and publication.
- SUNA uses shared persistent temporal-pattern resources and the original global
  RNG transaction. Native arguments/count/phase triggers stay here. DRAW and
  type-0 OVERRAP use those shared jobs and exact reviewed fixed-point mix rules.
- Text uses shared font measurement, fixed-cell layout, GlyphRuns and reveal;
  selections use shared UI interaction regions. Original Shift_JIS cell mapping,
  click advancement and history/window policy stay native. A translucent window
  composes through the shared mask-piecewise image operation and uses cropped
  engine image nodes, alongside separate GlyphRuns.
- Basic music/SE/voice lookup and volume policy feed shared buffered audio jobs,
  decoders and mixer. Single-source music0/1/N repeats use shared counted loop
  schedules, verified against real PCM completion. Native stepped fades,
  spatial policies and MML playlists still fail explicitly.

The reviewed callback profile is MUGEN2 Legacy1000, 16 effect slots. Other
versions are not inferred from similar filenames. Original save envelopes can be
parsed/round-tripped without discarding opaque fields; full VM/resource restore
is still unsupported. Normal Controller startup now has original Nothing, actual shared video-header
probe, Logo and the configured Opening background SPT. The legacy DirectShow
numeric codec status is never invented; header validation does not assert full
audio decode. Movie and Title now use shared Media/header probes, immutable ImageResources, UI widgets and audio. Remaining outer transitions and original-save reconstruction are incomplete.

`NativeAdapter` and `InstalledAdapter` expose a separate dependency-completion
pump; it does not sample input, advance clocks or schedule a new VM batch.
Shared operations also cover the exact grouped LayerGrey and masked/unkeyed
CTRANS profiles, native FadeOut11, persistent OldLamp109 and Bura74. Native six-rectangle/count/
trigger policy remains here; Bura uses shared16.16 piecewise resampling and
SUNA/Bura numeric curves map into shared progress envelopes. Original lamp Calcu
runs before all Print operations and shares the one native RNG transaction.

Ordinary picture/fill slots interleaved with screen effects are ordered shared
Composite inputs, including native picture-before-effect at the same slot. They
are excluded from the lower Canvas to avoid double rendering. Partial legacy
x86 picture masks use shared `MaskSeparate256`, with independent product floors;
window/CTRANS operations retain their distinct arithmetic profiles. No private
bitmap loop or second renderer lives in this crate.

Other periodic/delay/random native curve families and moving-rectangle profiles,
continuous effects during message waits, complete frame-debt scheduling and
later callbacks remain incomplete. One immutable player32 Controller acceptance
run reached348 original instructions/PC0x1d0 and published2568 native Title
frames with five enabled shared widgets and prepared BGM. It then failed
explicitly at the unimplemented autoRestart-to-Opening transition; no final PNG
or visual Title/Start/story acceptance was obtained. This source-module work is
newer than player33 and has not been linked into another desktop artifact.

See HANDOFF.md and STATUS.md for separate implementation, release compilation
and behavior evidence. No game/font/module data or unlicensed original source
is distributed. Shared algorithms can be used without this VM.


The reviewed SystemFile module preserves the original10-record58432-byte
format and its opaque/padding fields. Native flag/index/default/variable/name
policy remains here; reusable packed-bit operations, Gregorian weekday queries,
scoped storage and asynchronous atomic writes belong to Core/Runtime. Installed
bootstrap samples real client-scoped civil time, then prepares original defaults,
contiguous CG/project limits and saved200..299 variables on a resource worker.
MainControl and game configuration are distinct native tables; random seed
selection reads the former. The native no-srand branch requires actual startup
RNG state instead of inventing one.

An accepted window close freezes new native batches and drains admitted resource
work without acknowledging an unknown call. It waits for the reviewed Game-loop
and End SystemFile writes separately before halting. This global preference/
progress file is distinct from native dataN.sav game-state/resource restoration;
that full original-save import/export remains unsupported. Remaining progress
callback/calculated-variable consumers and full outer mode families still need
source-complete mapping. No new original-game run has been used to claim these
source changes are fully integrated.

Native `savesystemfile` is an asynchronous semantic adapter over scoped civil
clock and atomic storage receipts; an ordinary postfix candidate commits once,
only after the write succeeds. The legacy optional ResultData extension and
resource-write-bound arguments require additional native plans and fail before
admission. Native `layer` updates shared retained visibility and the following
Canvas frame, without sampling a privately rendered screen.

Script `week`/`holiday` reads use the current original date/year words and the
engine's shared Gregorian weekday calculation. Configured holiday tuples are
prepared on the existing bootstrap worker from `nya/saijitsu.xtx`; their original
exact-year and token grouping rules remain native policy. System clock fields
require distinct live async bindings and remain explicit gaps. These source
families have separate authored verification and do not establish full Title,
Start/story or native original-save compatibility.

The original five `expmode` and five `expcheck` calculated bindings read the
prepared original SystemFile preferences on native VM admission. They do not
alias stored script words, and later same-prefix names remain ordinary variables
as in the authenticated legacy constructor. This is independent of implementing
the native configuration screen that may later mutate those preferences.


Original audio work now has its reviewed16-word layout, independent of the
12-word callback ABI. Saved record round-trip retains five additional words,
all64 bytes of each voice name and unrelated status fields. Ordinary callbacks
reorder fields explicitly; Stop/Title ClearWork clear only native loop word0.
A saved63-byte filename is replayed directly rather than truncated again as a
new callback. Actual536740 restarts8sound/4voice; other voice rows stay retained.
`native_save_audio::SavedAudioPreparation` validates the whole original profile,
resolves sources on a cancellable native-policy worker and prepares shared
AudioReplacement resources without changing live/peer playback or clocks.
Its result still needs the complete original VM/Bridge/message/selection/effect
restore consumer; dataN load remains unsupported. Final release lib57passed,
1ignored, with real PCM/source workers; no new game/GPU acceptance is implied.
